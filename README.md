# 1주차를 통한 참고 사항

## Git 관련 참고 사항

- commit 메세지 중 '수정중' 이라는 표현보다는 해당 커밋에서 어떤 부분이 어떻게 수정되었는지 구체적으로 명시할 것
- .gitignore 파일을 통해 불필요한 파일이 커밋되지 않도록 설정해보기

## 클린코드 참고 사항

- 1주차에 사용했던 ln, nl과 같은 축약형의 변수명 사용이 아닌, length, newLineIndex같은 풀 네임을 적을 것
- 메서드의 이름을 더욱 구체적으로 적을 것
- isTure 같은 변수 명보다는 해당 변수가 나타내는 의미를 명확히 하는 것이 더 좋음
- 공백 사용이 일관적이지 않는 부분이 있어 신경을 써야함 IDE의 코드 자동 정렬 기능을 사용할 것
- 의미 없는 주석을 너무 많이 사용함. 변수명을 정확히 해서 주석이 필요 없을정도로 할 것

## 디버깅 참고 사항

- 1주차에는 console.log()를 사용해 디버거했지만, IDE의 디버거를 사용해서 복잡한 조건문을 이해할 것

## API 참고 사항

- 음수처리 시 while문을 통해 기능을 구현했지만, 정규표현식과 match() 또는 split() 메서드를 활용해서 간결하고 효율적으로 구현할 것

## 2주차 시작 전 참고사항

- 요구사항을 꼼꼼히 읽고, 구현 전에 명확히 이해할 것
- 들여쓰기는 2까지
- 3항 연산자 사용하지 않기 (코드의 가독성을 위하기 때문)

# 2주차 구현

## 구현 시작 전

- "어떤 상황일 때, 큰 함수를 단일 함수로 수행하는 작은 함수로 분리할 것인가?" 생각해보기
- Jest 테스트 도구를 사용하는 방법을 배우고 어떻게 적용시킬지 생각해보기

## 구현할 기능 목록 리스트 (시작 전)

- 입력 형식과 출력 형식을 만들기
- 쉼표(,)를 기준으로 입력받은 이름을 나누는 기능 만들기
- 받은 이름들의 길이가 5 초과라면 오류를 내보내는 기능 만들기
- 0~9 까지의 무작위 숫자를 구하는 기능 만들기
- 무작위 숫자가 4이상일 때 전진 기능 만들기
- 사용자가 입력한 시도 숫자 중간에 현재 상황 출력하는 기능 만들기
- 시도 숫자 마지막에는 전진의 길이를 구한 후 가장 높은 사람이 최종 우승자로 출력하는 기능 만들기

## 구현 전 생각

- 게임같이 만드려면 중간에 경주 상황 출력 기능에 지연시간을 걸어 더 게임같이 나오게 해볼까?
- 구현 난이도는 안높을거 같으니, Jest를 열심히 공부해보자
